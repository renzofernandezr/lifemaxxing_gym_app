# Decisiones

Registro de decisiones tomadas durante la construcción (fecha · decisión · por qué).

| Fecha | Decisión | Por qué |
|---|---|---|
| 2026-10-21 | Node 22 LTS vía `fnm` (`.nvmrc` = 22); pnpm 12.14.0 vía corepack de Node 22. | La Mac tiene Node 26, que ya no trae corepack; el plan pide Node 22 y el Dockerfile usa `node:22`. |
| 2026-10-21 | `nodeLinker: hoisted` en `pnpm-workspace.yaml` además de `.npmrc`. | pnpm ≥ 11 ignora la configuración de `.npmrc`; sin esto instalaba con enlaces aislados. |
| 2026-10-21 | Expo SDK 58 (plantilla `default`): las rutas viven en `apps/mobile/src/app/`. `web.output` = `single`. | Es la estructura de la plantilla actual. `single` genera una SPA estática que la API sirve con fallback a `index.html`. |
| 2026-10-21 | TypeScript ~6.0.3 en todo el monorepo (la versión que fija la plantilla de Expo). | Evita dos compiladores distintos; TS 7 aún no lo soporta Expo. |
| 2026-10-21 | Los datos del programa (ejercicios, fases, rutinas) viven en `packages/core/src/program.ts` y el seed `0002_seed_program.sql` se genera desde ahí (`pnpm --filter api gen:seed`). | Una sola fuente de verdad para la DB y para la vista Plan sin conexión. |
| 2026-10-21 | `macros()`: redondeo al entero más cercano y, en el empate exacto (x.5), hacia abajo. | El vector del plan `macros(2600)` → C 292 exige que 292.5 baje; así además no se pasa de las kcal. |
| 2026-10-21 | `stepOf()` usa el `increment_kg` del ejercicio si es > 0; si no, 2 kg en mancuernas y 2.5 kg en el resto. | Así lo pide el plan; coincide con el prototipo en todos los ejercicios calibrables. |
| 2026-10-21 | `isRecord()` sin historial devuelve `false` (la primera sesión es la "base", no un récord). | En el prototipo la sesión de calibración tampoco cuenta como récord. |
| 2026-10-21 | Rampa Kino con más de 4 series (box squat 5 × 6): se extiende la rampa hacia atrás con −0.12 por serie. | El prototipo solo define 4 factores (.64/.76/.88/1). |
| 2026-10-21 | Cambio de peso a mitad de un RPT recalcula **todas** las series siguientes (no solo la próxima). | El plan dice "las siguientes se recalculan". |
| 2026-10-21 | `citext` se crea `with schema public` en 0001. | Los tests corren en un schema propio (`search_path=test_x,public`); así comparten la extensión y no se duplica. |
| 2026-10-21 | Migración extra `0003_session_summary.sql`: columna `summary jsonb` en `workout_sessions`. | El resumen (volumen, récords, próximo peso) se calcula al terminar y se guarda; el historial y la actividad no recalculan. |
| 2026-10-21 | `register` inicia sesión al crear la cuenta (cookie o token según el cliente). | Evita un segundo paso de login. Sigue limitado a `ALLOWED_EMAILS`. |
| 2026-10-21 | Rate limit: se cuentan intentos fallidos por email **y** por IP (`X-Real-IP` / primer `X-Forwarded-For`) en 15 min; con 5 → 429 aunque la contraseña sea correcta. | Así lo pide el plan; la IP puede falsearse, pero el límite por email sigue protegiendo la cuenta (app personal). |
| 2026-10-21 | CSRF: con cookie, los métodos que modifican exigen `Origin` (o `Referer`) del propio host o de `ALLOWED_ORIGINS`. Login/registro web también lo validan si llega `Origin`. Con Bearer no aplica. | Plan §7.1. `ALLOWED_ORIGINS` (por defecto `localhost:8081` fuera de producción) permite Expo web local contra la API local con CORS + credenciales. |
| 2026-10-21 | `discard` también acepta sesiones terminadas (las saca del historial y de las estadísticas). | El resumen ofrece "Descartar" después de `finish`, y el smoke test limpia así sus datos. |
| 2026-10-21 | `finish` sin series de trabajo → 400 `empty_session`. | Una sesión vacía no debe contar como entreno. |
| 2026-10-21 | Rutas de pestañas como archivos planos (`(tabs)/progreso.tsx`, `entrenar.tsx`, `plan.tsx`) en lugar de carpetas con `index.tsx`; pestañas headless de `expo-router/ui`. | Mismo URL (`/progreso`…) y control total del diseño: barra inferior con botón central y pestañas en la cabecera en escritorio. |
| 2026-10-21 | Calentamientos calculados: solo en el primer ejercicio con carga de la sesión (pirámide o Kino, sin peso corporal) y solo si no hay serie de prueba. | Plan §9.3 ("solo en el primer ejercicio"). En B el primero es negativas (peso corporal), así que el calentamiento va en el jalón, como en el prototipo. |
| 2026-10-21 | Peso inicial de la serie de prueba sin historial: barra 40 kg, mancuernas 10 kg, polea 25 kg. | El prototipo usaba 85 % de la última carga, que no existe en la primera sesión. |
| 2026-10-21 | Empezar un entreno requiere conexión (crea la sesión en la API). Después, cada serie se guarda en el store local y se sincroniza en lote con reintentos; "Terminar" exige que la cola esté vacía. | Evita ids temporales de sesión; el resto del entreno funciona sin red. |
| 2026-10-21 | Modo demo (`?demo=1`, solo web) con datos simulados deterministas y entrenos/check-ins en memoria; el usuario demo usa un correo ficticio. | El plan pide demo solo con `?demo=1`. Sirve para capturas y para probar la UI sin DB. Nunca se activa en nativo ni sin el parámetro. |
| 2026-10-21 | Ícono propio (disco naranja del prototipo) generado con `apps/mobile/scripts/gen-icons.mjs` (PNG sin dependencias). | La plantilla traía el logo de Expo. |
| 2026-10-21 | La API sirve la web con fallback a `index.html` solo para rutas sin extensión; `/_expo/*`, `/assets/*` y archivos inexistentes dan 404. | Un asset faltante devolvía HTML con 200 y rompía la carga con errores confusos. |
| 2026-10-21 | `programPosition` cuenta las semanas desde el **lunes** de `program_start_date` (aunque se guarde otro día). | Si no, una fecha de inicio en miércoles rompía la alternancia A/B. |
| 2026-10-21 | En peso corporal (`peso_corporal`, `rueda`) el piso de carga es 0 y en pirámide ninguna serie supera a la anterior. | `Math.max(paso, …)` hacía que 0 kg de lastre diera series 2 y 3 con +2.5 kg. |
| 2026-10-21 | `POST /sessions/:id/discard` acepta `{ onlyInProgress: true }`: si la sesión ya terminó responde 409 y la app muestra su resumen. Sin el flag (pantalla de resumen) sí descarta una terminada. | Si se perdía la respuesta de `finish`, "Descartar" era la única salida y borraba el entreno. |
| 2026-10-21 | La app guarda una copia de `me` en AsyncStorage y solo un 401 cierra la sesión. | Abrir la app sin red en el gimnasio no debe sacarte del entreno en curso. |
| 2026-10-21 | Timeout de 15 s en cada petición (se trata como "sin conexión" y se reintenta). | En Android `fetch` no tiene timeout y una petición colgada bloqueaba la cola. |
| 2026-10-21 | El modo demo también se activa en desarrollo con `EXPO_PUBLIC_DEMO=1` (`pnpm --filter mobile demo`), además de `?demo=1` en web. Exige `__DEV__`, así que nunca entra en una build de producción. | Con Railway caído no hay API: es la única forma de ver la app en Expo Go en el iPhone. |
| 2026-10-21 | **Bajar de Expo SDK 58 a SDK 57** (Expo 57.0.31, React Native 0.86.3, React 19.2.3) y quitar dependencias de la plantilla que no se usan (`@expo/ui`, `expo-glass-effect`, `expo-symbols`, `expo-image`, `expo-web-browser`, `expo-device`). | Pedido de Renzo: el Expo Go de la App Store todavía es SDK 57 (el de SDK 58 sale "en unas semanas"), y con 58 no se podía abrir en su iPhone. Cuando la tienda publique Expo Go 58 (que solo soportará 58): `cd apps/mobile && npx expo install expo@^58.0.0 --fix`, actualizar el override de `@react-native/metro-config` en `pnpm-workspace.yaml` y correr typecheck/tests. |
| 2026-10-21 | Rediseño de la sesión en curso sin scroll (pedido de Renzo, inspirado en Hevy/Strong y Fitbod): tira de ejercicios arriba (uno a la vez), tabla de series con columnas Anterior · Kg · Reps · ✓, y panel inferior fijo con los steppers grandes y "Registrar serie". La técnica y la alternativa son plegables; tocar una serie hecha permite corregirla desde el panel. | La versión anterior apilaba una tarjeta grande, la tabla y la lista, y había que bajar para registrar. |
| 2026-10-21 | El descanso se abre a pantalla completa por defecto (anillo a todo el ancho, cuenta grande); "Minimizar" lo deja como barra sobre el panel. En la previa, "Empezar entrenamiento" queda fijo abajo. | Pedido de Renzo: el contador debe ocupar toda la pantalla y no hacer scroll para empezar. |
| 2026-10-21 | En Progreso y Plan (móvil) el título y las sub-pestañas quedan fijos; solo hace scroll el contenido de la sub-pestaña. El margen final es de 24 pt y solo crece cuando la barra de descanso minimizada está visible. | Pedido de Renzo: el relleno fijo de 120 pt dejaba demasiado espacio al final del scroll. |
| 2026-10-21 | La app se llama **Life Maxxing** (nombre visible, web y splash). El repo, el slug de Expo y el bundle id no cambian. Login y registro con un diseño más limpio (logo y nombre centrados, campos amplios, "Mostrar" contraseña). | Pedido de Renzo. Cambiar slug o bundle id complicaría EAS sin aportar nada. |
| 2026-10-21 | Se quita el botón de tema (día/noche) de la cabecera: el tema se cambia en Ajustes. | Pedido de Renzo: estaba duplicado. |
| 2026-10-21 | Ajustes como lista agrupada (nombre, altura, peso meta, inicio del programa; tema; cerrar sesión), sin "Peso inicial" (sigue en el perfil y lo usa Progreso, solo no se edita aquí). "Guardar cambios" aparece solo si hay cambios. | Pedido de Renzo: más limpio, correo separado del nombre y sin margen de más arriba. |
| 2026-10-21 | Hápticos: toque suave en botones, más firme en los principales, seco en la cuenta 3-2-1 y vibración larga al terminar el descanso (iOS: 3 pulsos con `Vibration`; Android: patrón de ~2.5 s). En web no vibra al tocar. | Pedido de Renzo. |
| 2026-10-21 | Sesión en curso rediseñada como **una serie a la vez** (pedido de Renzo, que eligió este estilo entre tres): nombre grande, "Serie N de M" con el objetivo en una píldora, dos tarjetas grandes de kg y reps con botones redondos, una sola pista, botón ✓ "Hecho" grande, puntos de las series (tocar uno hecho lo corrige) y Ejercicios / Técnica / Saltar en hojas inferiores. | La versión con tabla y panel le parecía cargada y plana. |
| 2026-10-21 | Anillo de descanso fino (pista de 5, arco de 8 con degradado y halo), sin el dial en relieve. Vibración final de ~3 s en iOS (6 pulsos) y ~4 s en Android. | El dial 3D se veía muy grueso. |
| 2026-10-21 | El descanso va **dentro** de la sesión, en el mismo lugar que la serie (serie → descanso → serie, con deslizamiento), sin capa encima ni puntos extra; el botón de abajo pasa a "Saltar descanso" / "Empezar siguiente serie". Anillo plano como el prototipo (sin relieve). Fuera de la sesión se muestra la barra flotante, que lleva de vuelta a la sesión. | Pedido de Renzo. |
| 2026-10-21 | El prototipo (modo demo) arranca en la semana 8, la última de la Fase 1 (antes semana 9, Fase 2). | Pedido de Renzo: que muestre la Fase 1 con historial. |
| 2026-10-21 | Dos modos de demo: `pnpm --filter mobile demo` (historial, semana 8) y `pnpm --filter mobile demo:nuevo` (usuario nuevo en la semana 1, sin historial ni 1RM: A y B empiezan con series de prueba). En web: `?demo=1` / `?demo=nuevo`. | Pedido de Renzo: ver la medición del 1RM de la primera sesión, que con historial simulado no aparece. |
| 2026-10-21 | TestFlight sin servidor: perfil EAS `demo` (`EXPO_PUBLIC_DEMO=1`) que activa la demo también en el build de release; los perfiles `preview` y `production` siguen usando la API real. El mundo de la demo (historial, sesión en curso, check-ins) se guarda en AsyncStorage (`lmx-demo-world-v1`), así que cerrar la app a mitad del entreno no pierde las series. | Railway sigue caído y Renzo quiere publicar ya, sin Fly ni Neon. |
| 2026-10-21 | iOS: ícono sin canal alfa (`icon-ios.png`, App Store Connect lo exige) y expo-audio sin permiso de micrófono ni audio en segundo plano (la app solo reproduce pitidos; el aviso con la app cerrada va por notificación local). | Evitar rechazos al subir el build y permisos que la app no usa. |
| 2026-10-21 | **Servidor en Render en lugar de Railway (por ahora), todo en plan gratis**: Postgres `lifemaxxing-gym-db` (free, Postgres 18) y servicio web Docker `lifemaxxing-gym` (free), ambos en Virginia, desde `feat/app-rn` con auto-deploy. Solo hay `production`: no hay entorno `dev`. Se crean con la CLI de Render (`scripts/render-setup.sh`). Los archivos de Railway se conservan. | Pedido de Renzo: Railway sigue caído y quiere todo gratis. Render solo permite una Postgres gratis por workspace, así que no alcanza para `dev`. Límites del plan gratis: la web se duerme tras 15 min sin tráfico (~1 min en despertar) y la Postgres no tiene backups y **caduca el 21-nov-2026** (14 días de gracia para pasarla a pago; luego Render la borra con los datos). |
| 2026-10-21 | La Postgres de Render queda sin IPs permitidas: solo acepta conexiones de la red privada (el servicio web usa la URL interna). | Nada fuera de Render necesita conectarse; sin `dev` no hay migraciones ni tests desde la Mac. |
| 2026-10-21 | Recursos de Render sin proyecto ni entornos de Render. | La CLI 2.30 no crea proyectos (solo los lista). Se pueden agrupar después desde el dashboard. |
| 2026-10-21 | En la PC de `~/Repositories` se usa **nvm** (ya instalado) en vez de fnm para Node 22. | Lee el mismo `.nvmrc`; evita instalar otro gestor de versiones. |
